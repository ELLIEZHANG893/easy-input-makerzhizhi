## 二、ESP-IDF 默认构建

### 仓库的版本化声明

- `dependencies.lock`：`idf` 版本 `5.5.5`，`target: esp32s3`。
- `components/esp_hid/CMakeLists.txt`：要求 `idf_ver == v5.5.5`，否则构建失败。
- 根 `CMakeLists.txt`：只接受 `IDF_TARGET=esp32s3`；`EASY_INPUT_BOARD` 默认且只能为 `v2`。
- 与课程基线（5.5.5 / ESP32-S3）一致，无冲突。

### 执行环境与工具版本（实测）

- 云端与用户电脑上的 Linux 环境访问乐鑫组件服务器均被网络策略拒绝（403），无法按锁文件拉取组件；没有改用替代来源。构建改在用户 Mac 终端执行，由仓库外的一次性脚本完成。脚本先核对源码树哈希一致（`TREE_MATCH=yes`，工作区 0 个改动），再激活并构建，全部输出写入本地日志。
- ESP-IDF：`idf.py --version` 为 `ESP-IDF v5.5.5`，`git describe` 为 `v5.5.5`。
- 目标：`esp32s3`（构建输出 “Building ESP-IDF components for target esp32s3”，镜像为 esp32s3 image）；板型 `v2`；Flash 16MB。
- 工具链：`xtensa-esp-elf` GCC 14.2.0（`esp-14.2.0_20260121`）；esptool v4.12.0；Python 3.14.6；CMake 4.3.4；主机 Darwin arm64。
- 构建生成器为 `Unix Makefiles`：环境中没有 `ninja`，`idf.py` 自动退回 Make。这不影响构建结果，但与官方默认的 Ninja 不同，记录为工具差异。
- 组件：使用锁定版本 `espressif/esp_tinyusb 1.7.6~2`、`espressif/tinyusb 0.21.0~1`。组件管理器提示 `tinyusb` 有 `0.21.0~2` 可用，仅为提示，**未更新锁文件**。
- 方式：`idf.py fullclean` 后 `idf.py build`，退出码 0，用时约 102 秒。
