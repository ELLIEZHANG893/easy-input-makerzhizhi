# T20 · 正常模式连接、App 配置同步与真实功能验证

> 在 T19 写入并正常重启的实板上，通过 EasyInput App 建立正常模式连接，由 App 为一个实体键生成“UUID → 本机应用”映射并同步，再由使用者逐项观察七项真实功能。本节点不烧录、不修改固件、不手写 UUID、不修改 App。

- **结论**：`FUNCTION_VERIFIED=YES`（同步已由界面明确确认，七项均由使用者亲自观察通过）。
- **前置**：T19 的 `DEVICE_CONFIRMED`、`FLASH_WRITTEN`、`NORMAL_POWER_CYCLE_CONFIRMED` 均为 YES。

## 条件

| 项 | 值 |
|---|---|
| 开发板 | EasyInput V2.0（固件板型 `v2`），设备 MAC 后四位 `9ea0`，固件为 T19 写入版本（`0.4.53-idf-v2-ble-store-v1`） |
| App | EasyInput 官方正式版 **0.1.51**（“当前已是最新版本”），只运行一个实例；与课程复验用过的 0.1.26 不同，版本差异不作为失败依据 |
| 主机 | macOS；键盘模式 macOS |
| 观察方式 | 使用者在主机上亲自操作和观察；Agent 只给出步骤、读取截图与回复 |

## 映射与同步

- 原有 KEY8 为“打开应用 → SeaTalk”（此前建立）。本次按使用者选择在 KEY8 上重新选择“打开应用”，目标改为系统自带的 Calculator，UUID 由 App 生成，Agent 未接触或手写 UUID。
- 为覆盖“原有快捷键”检查，KEY7 临时由“撤销”改为自定义快捷键 Command ⌘ + Z（只改 App 配置）。
- 第一次同步后发现 KEY1 被误改为 Calculator、KEY7 只录到 Command：属于配置内容错误，不是同步失败。修正为 KEY1 语音输入、KEY7 Command ⌘ + Z 后再次同步。这不占用“断开重连并重试同步一次”的机会，该机会未使用。
- **保存证据（界面明确确认）**：右下“已同步 ✓”与提示“设置已同步到键盘。”，配置空间 1198／2048 字节；界面所示键位为 KEY1 语音输入、KEY2 语音编辑、KEY3 全选、KEY4 复制、KEY5 粘贴、KEY6 固定文字、KEY7 ⌘Z、KEY8 Calculator（打开应用）。界面确认清楚，因此未读取额外诊断。

## 七项真实功能（均由使用者观察）

| # | 项 | 条件与操作 | 使用者观察 | 结果 |
|---|---|---|---|---|
| 1 | USB-only | 关闭主机蓝牙，只连 USB；在文本编辑中按 KEY8 | 计算器打开 | 通过 |
| 2 | BLE-only | 拔掉 USB，开发板用电池保持开机，主机蓝牙连接开发板；按 KEY8、KEY6 | 蓝牙已连上；计算器打开且只一次；固定文字只出现一次 | 通过 |
| 3 | 双连接不双发 | 蓝牙保持连接并插回 USB（App 底部显示“USB 连接”）；按 KEY6、KEY8、KEY4＋KEY5 | 固定文字一次；计算器只打开一次；粘贴结果一份 | 通过 |
| 4 | 按下一次只触发一次 | 计算器退出后快速按一次 KEY8 | 只出现一个窗口、只打开一次、没有闪两次 | 通过 |
| 5 | 松开不重复 | 计算器退到后台后按住 KEY8 两秒再松开 | 松开后不重复触发 | 通过 |
| 6 | 原有复制／粘贴／快捷键／固定文字 | 文本编辑中：KEY6；KEY3＋KEY4，KEY5；KEY7（⌘Z） | 固定文字一次；复制粘贴正常；⌘Z 撤销粘贴 | 通过 |
| 7 | 目标应用实际打开 | 按 KEY8 | Calculator 实际启动 | 通过 |

## 说明与边界

- 双连接项中，“打开应用”即使被发送两次，肉眼看到的也可能只是同一个窗口。因此单通道的直接可见证据来自同一时刻的固定文字只出现一次、粘贴只出现一份；计算器只打开一次作为补充观察。双连接时 App 底部显示 USB 连接，与固件 `UsbFirst` 单通道路由一致；该时刻蓝牙是否仍保持连接，以使用者按步骤保持为准，未另行截图。
- BLE-only 项中，App 底部的蓝牙状态未截图，以使用者确认“蓝牙已连上”为准。
- 未测试 Windows 平台、编码器、其他实体键的 Host Action，也未测试长时间稳定性。
- 测试用配置仍在开发板上：KEY7 为 ⌘Z、KEY8 为 Calculator。是否恢复为“撤销”和 SeaTalk 由使用者决定，恢复只需在 App 中修改并同步。
